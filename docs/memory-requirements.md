## 1. 结论摘要（一页版）

Zero 现状：**有任务粒度的日志持久化与 `/resume` 续跑，没有跨任务记忆**。本次要为它补一套「可写入、可注入、可检索、可管理」的记忆系统，并把「从过去经历中学习、迭代进化」收敛成**记忆驱动的代码改进建议（生成补丁，由人合并）**，而不是 Agent 自动改 main。

| 维度 | 已确认结论 |
|---|---|
| 目标 | 用户偏好跨任务保留、历史任务结论可复用、环境与事实沉淀、从经历中迭代进化 |
| 作用域 | **项目级 + 用户级两层**（项目按 `project_root` 隔离，偏好全局生效） |
| 写入 | **显式 `/remember` + 任务结束自动提炼**；自动提炼仅收尾触发、失败静默；先入**暂存区**，用户批量确认后才入库 |
| 读取 | **注入系统固定区（pinned_system）+ 按需检索工具**，两者都要；已注入条目不在检索里重复出现 |
| 进化边界 | 允许「自我修改代码」的诉求，但落地为**仅生成 `.patch` 到任务 workspace + TUI 提示路径**，由人合并；不建分支、不 commit、不 push |
| 一期范围 | 关键词/标签检索、TUI 管理面板（`/memory` + 候选角标）；向量语义检索以 **`MemoryIndex` trait 抽象**预留接口，一期不实现真实 embedding |
| 容量策略 | 记忆库：上限 + 去重 + 新覆盖旧（保留历史版本）+ LRU 淘汰；注入量：**按 token 比例动态截断**，不设硬条数上限 |
| 冲突裁决 | 用户级与项目级同 key 冲突时**两条都注入并标注来源**，由模型判断 |
| 子任务 | **不继承记忆，完全隔离**；需要背景由父任务写进 `goal`/`context` |
| 隐私红线（已裁决） | **仅禁密钥与凭据**，命中即拒绝并脱敏；另加最小兜底：每条写入限长 + 来源/时间戳记录 |
| 存放 | 用户级 `~/.config/zero/memory.jsonl`；项目级 `<project_root>/.zero/memory.jsonl`，`.zero/` 加入 `.gitignore` |
| 验收 | §7 八条**全采纳** |
| 明确不做（一期） | 跨设备同步、自动合并/推送代码、子任务记忆继承、真实向量库落地 |

## 2. 现状基线（为什么这不是「加个文件」就行）

| 已有机制 | 位置 | 与记忆的关系 |
|---|---|---|
| 事件 JSONL 落盘 | `agent-store` | 是**日志**，不是记忆：可读性面向审计回放，不向新任务注入 |
| `resume_context()` | `agent-store/src/lib.rs` | 从 `ContextSnapshot` 还原**当时真正送给模型**的消息；仅 `/resume` 手动触发（v1.2 起改为按 `added`/`reset` 增量序列重建，见 `docs/context-audit.md`） |
| `ContextManager` 三层 | `agent-runtime/src/context.rs` | 固定系统区（永不丢弃）、最近 12 条消息、旧轮次轻量摘录；**任务一结束即销毁** |
| 大输出外置 `ctx/` | 同上 | 文件外置层，路径可复用但不带语义 |
| 子任务上下文隔离 | `agent-runtime/src/subagent.rs` | 注释明确「子任务永远是全新上下文」，刻意不复制父历史消息 |
| 权限与事件穷尽匹配 | `agent-perm` / `agent-tui` / `xtask` | 新增工具与事件会牵动多处穷尽 match（历史上踩过 3 处） |

**关键判断**：记忆系统的主要工作量不在「存」，而在 **写入准入、注入预算、作用域裁决、可追溯删除** 这四件事上；否则就是把幻觉和噪音永久固化进 system 提示词。

## 4. 已确认需求逐条展开

### 4.1 记忆条目模型（概念层，非最终类型设计）

一条记忆至少应能回答五个问题，否则无法支撑后面的裁决：

| 字段 | 用途 |
|---|---|
| `scope` | `User` / `Project(project_root)`，决定注入哪个任务 |
| `content` | 一句话事实/偏好/经验，不存大段原文 |
| `tags` / 关键词 | 关键词检索与按需检索的召回依据 |
| `source` | 来源任务 id、时间戳、写入方式（显式 / 自动提炼 / 批量确认） |
| `state` | `Candidate`（暂存区）/ `Active`（生效）/ `Archived`（淘汰但可追溯） |

> 「保留历史版本」来自 Q11 的冲突处理约定；「可追溯」虽未在 Q7 勾选，但它是「批量确认」「删除」「回滚误写」的前提，列为待确认 O1。

### 4.2 写入双通道

```
显式 /remember ──────────────────────────────► Active（立即生效）
任务收尾自动提炼 ─► Candidate 暂存区 ─► 批量确认 ─► Active
                                      └─► 丢弃（不入库、不注入）
```

- 自动提炼**不得**绕过暂存区直接进 `Active`（Q6）。
- 显式命令与自动提炼都要走同一条**准入管道**：密钥扫描 → 去重 → 作用域判定 → 落盘。
- 「从经历中迭代进化」的可审计形态：记忆里存的是「遇到 X → 采用 Y 有效 / Z 失败」这类**经验事实**；由这些事实触发代码改进建议（Q9），不是让模型直接拥有写仓库的权限。

### 4.3 读取双通道

| 通道 | 规则（已裁决） |
|---|---|
| 注入系统固定区 | 新任务启动时，把「用户级 + 本项目级」条目拼进 `ContextManager::new` 的 `pinned_system`；**按 `max_context` 比例动态截断**（O3），不设硬条数上限 |
| 按需检索工具 | 新增 `memory_search` 类工具，按关键词/标签/作用域召回；走 `TaskSpec::allows_tool` 可见性规则 |

> 两个通道并存意味着一条记忆可能被重复送进上下文，设计阶段需要定义「已注入的不在检索结果里重复出现」的约定。

### 4.4 作用域与优先级

- 项目级按 `project_root` 隔离；`project_root` 为空（纯 workspace 任务）时**只注入用户级**，避免不同临时任务互相串味。
- 同 key 冲突时**两条都注入并标注来源，由模型判断**（O2 裁决，非「项目级覆盖用户级」）。设计文档需定义标注格式与去重约定。

### 4.5 一期范围与二期预留

**一期交付**：关键词+标签检索、`MemoryIndex` trait 抽象、TUI 管理面板（查看 / 搜索 / 编辑 / 删除 / 清空 / 候选批量确认）、两层作用域、注入 + 检索双通道、准入管道、容量淘汰。

**二期预留（本期不实现）**：真实 embedding / 向量库、`SyncEndpoint` 跨设备同步、子任务记忆继承、自动合并补丁。

## 7. 验收标准（**已确认**：O8 裁决为 8 条全采纳）

1. 新任务 A 执行 `/remember`，**关掉进程**再开任务 B：B 的 system 固定区含该条目。
2. 在仓库 X 写入的项目级记忆，切到仓库 Y 的新任务**不可见**。
3. 含 PAT / API key 格式的文本经任一写入通道都被拒绝，且落盘内容不含该串。
4. 自动提炼产生的候选在批量确认前：不注入 system、检索不到、`state == Candidate`。
5. 达到上限后继续写入，最久未用条目被淘汰；冲突写入保留历史版本可查。
6. `delegate` 子任务：既看不到记忆注入，也调不到记忆工具（`tool_allowlist` 断言）。
7. TUI 面板可查看 / 搜索 / 编辑 / 删除 / 清空，删除后检索不再命中。
8. `cargo test --workspace` 全绿、`clippy --workspace --all-targets` 零告警、`fmt --check` 无 diff；不新增真实模型调用。

### 10.2 裁决带来的需求修正（设计阶段必须遵守）

1. **§4.3 注入预算**：由「硬上限」改为「按 token 比例动态截断」；设计需给出比例、截断顺序（保留高权重/最近使用）与可观测性。
2. **§4.4 冲突优先级**：由「项目级覆盖」改为「并存 + 来源标注」；检索结果同样要带来源标注。
3. **§5 R2 进化边界**：由「生成补丁 + 跑测试」收窄为「**仅生成 `.patch`**」，不跑测试、不碰 git。
4. **§5 R5 隐私**：维持最小红线；最小兜底（限长 + 来源/时间戳）写入设计文档的准入管道，并在 TUI 明示「本系统不限制 PII / 源码原文入库」这一已知限制。
5. **§1 摘要表**已按上述全部更新，以本表为准。

### 10.3 评审时确认接受的风险

- O1 + O2 + O3 组合：**冲突记忆同时进 system**、**注入量随上下文窗口浮动**、**PII/原文可能被自动提炼写入**。项目所有者已明确选择「加最小兜底、接受风险，照裁决走」。
- 该组合下，「已注入的不在检索里重复出现」的约定更重要：设计文档需给出明确的去重键与预算计算方式。
